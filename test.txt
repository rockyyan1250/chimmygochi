# CHIMMY育成ゲームを作るために必要なもの

## まず結論

現在お持ちの **Waveshare本体・パソコン・USBケーブル・microSD・スピーカー・電池**があれば、主なハードウェアはそろっています。

**最初から追加の電子部品をたくさん購入する必要はありません。**  
これから重要になるのは、次の3つです。

1. **実機で画面・タッチ・音・microSDが一緒に動くか確認する**
2. **BABY CHIMMYの画像・アニメーション・音などの素材を用意する**
3. **時計・育成ゲーム・保存機能のプログラムを作る**

以下、必要なものと制作順序を詳しく整理します。

---

# 1. 必要なハードウェア

## 1-1. すでにお持ちのもの

| 物 | 数量 | 用途 | 現在の状況 |
|---|---:|---|---|
| Waveshare ESP32-S3-Touch-AMOLED-2.16 | 1台 | ゲーム本体 | お持ち |
| パソコン | 1台 | プログラム開発・画像編集 | お持ち |
| USBデータケーブル | 1本 | 電源供給・プログラム書き込み | 接続済み |
| microSDカード | 1枚 | 画像・アニメ・音声の保存 | お持ち。容量・形式は未確認 |
| スピーカー | 1個 | 効果音・反応音 | お持ち。接続・仕様は未確認 |
| 電池 | 1個 | 将来の持ち運び用 | お持ち。仕様は未確認 |

このボードには、メーカー資料上、画面・タッチ機能・時計用RTC・電源管理回路・音声回路が搭載されています。

そのため、**最初は別の画面、RTCモジュール、音声再生モジュール、Raspberry Piなどを追加する必要はありません。**

> ただし、個々の機能や同時動作が現在の実機で問題なく動くことは、まだ確認していません。

## 1-2. 必要になる可能性があるもの

| 物 | 必要な場合 | 注意点 |
|---|---|---|
| **microSDカードリーダー** | PCからmicroSDへ素材をコピーする場合 | PCにカードスロットがあれば、対応アダプターで足りる場合もあります |
| **USB電源アダプター** | パソコンにつながず卓上で使いたい場合 | 安定した5V USB出力のものを選びます |
| **ケース** | 電子基板や電池を保護したい場合 | 本体・電池・スピーカーの寸法を確認してから選びます |
| **絶縁された作業台** | 基板をケースなしで試験する場合 | 金属の机や導電性の物に基板を直接置かないようにします |
| 小型ドライバーなど | ケースに固定する場合 | ケースの構造が決まってからで十分です |

microSDはすでにお持ちなので、**まず現在のカードを確認**しましょう。新しく買う場合は、試験用として8～32GB程度を候補にできますが、対応は実機で確認が必要です。

素材の読み込みには、まず **FAT32** を試す設計です。既存カードをフォーマットすると中身が消えるため、**バックアップなしで初期化しないでください**。

また、ボードをUSBでPCにつなぐだけで、microSDがPCのドライブとして表示されるとは限りません。素材を入れるためにカードリーダーが必要になる可能性があります。

## 1-3. 電池についての重要な注意

現在の`電源スケッチ`には、次の設定が書かれています。

- 充電電流：**300mA**
- 充電目標電圧：**4.1V**
- 温度センサー測定：**無効**

これは「お持ちの電池に安全である」と確認された値ではありません。

電池を使用・充電する前に、少なくとも次を確認します。

- 電池の型番・公称電圧・容量
- 許容充電電流と充電条件
- 保護回路の有無
- コネクターの形と**プラス／マイナスの極性**
- 電池の温度管理方法

USB接続中に電池が接続されていると、充電される場合があります。**仕様を確認するまで、電池を使った充電試験は進めない方が安全です。**

最初の画面・プログラム開発は、電池の条件を確認したうえで、USB給電を中心に進めるのが簡単です。

# 2. 必要なソフトウェア

## 2-1. プログラム開発用

| ソフトウェア | 用途 | 状況 |
|---|---|---|
| **Arduino IDE 2** | プログラムを編集・コンパイル・書き込み | スクリーンショット上では導入済み |
| **Arduino-ESP32** | ESP32-S3向けの開発環境 | 実際に使用中の版は要確認 |
| **Arduino_GFX** | AMOLED画面の表示 | 現行スケッチでも使用 |
| **LVGL** | ボタン・画面切り替えなどのUI | メーカーの同梱例は8.4.0 |
| **XPowersLib** | 電源・電池情報の制御 | 現行スケッチでも使用 |
| **SensorLib** | タッチ・RTCなどの制御 | メーカーサンプルに同梱 |
| **SD / I2S関連ライブラリ** | microSD読み込み・音声出力 | 選んだArduino環境とサンプルに合わせる |

**バージョンを適当に混ぜないことが重要です。**

調査時点では、メーカーのArduino解説ページは3.3.5系のサンプルに言及し、公式GitHubはArduino-ESP32 3.3.11をテスト対象としています。まずどちらかの**一式を選んで動作確認**し、その後バージョンを固定します。

参考：[Waveshare公式Arduinoサンプル](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-2.16/tree/225a62bff11b5d0a0b607873860d39485a9a9685/examples/arduino)

## 2-2. 画像・音の制作に使うソフト

すべてを入れる必要はなく、制作方法に合わせて選びます。

| ソフト・種類 | 用途 | 必要性 |
|---|---|---|
| **Krita または GIMP** | 画像編集、背景透過、位置合わせ | 2D素材を作る場合に有用 |
| **FFmpeg** | 動画から画像を切り出す、音声形式を変換する | このPCでは利用可能なことを以前確認済み |
| **Audacity** | 音声の編集・音量調整 | 音を自分で作る場合に有用 |
| **Blender** | 3Dモデルのポーズ・アニメ制作 | 3D方式を選ぶ場合のみ |
| **AI画像／動画サービス** | 動きや素材制作の補助 | 任意。サービス・費用は未定 |

**有料AI、3Dプリンター、高性能GPUは最初の動作確認には必須ではありません。**

# 3. ゲーム用に必要な「素材」

電子部品とは別に、画面に表示する画像や音を用意する必要があります。

## 3-1. まず必要な最小素材

最初から大量の画像を用意するのではなく、まずは次の小さなセットを作ります。

| 素材 | 最初の目安 | 用途 |
|---|---:|---|
| キャラクター画像 | 1枚 | BABY CHIMMYを表示 |
| 部屋の背景画像 | 1枚 | キャラクターの後ろに表示 |
| 待機アニメ | 1種類 | まばたきや小さな動き |
| 効果音 | 1種類 | タッチ時の音など |
| ボタン画像・文字 | 数種類 | ゲーム、時計、設定など |

動作試験の最初は、**権利を確認した素材、またはCHIMMYではない仮の画像**でも構いません。先に端末の性能を確認するためです。

### 画像サイズの初期候補

- 画面全体：**480×480ピクセル**
- キャラクター：**256×256または320×320ピクセル**
- 原本：背景を透過したPNG
- 画面上では、背景とキャラクターを別々に合成する

これは実験用の候補で、最終サイズではありません。小さくしすぎて画質を犠牲にしないように、実画面で比較します。

## 3-2. 初版ゲーム用の素材案

`設計書`では、次を**初版の目標案**として考えています。

| 種類 | 数量の案 | 例 |
|---|---:|---|
| 衣装 | 3セット | 基本衣装、パジャマ、別の衣装 |
| 食べ物 | 6種類 | おにぎり、プリン、いちごなど |
| おもちゃ | 2種類 | ボール、しゃぼん玉など |
| 反応・動き | 8種類程度 | 待機、笑う、食べる、眠るなど |
| 部屋 | 1種類 | 基本の部屋 |
| 効果音 | 数種類 | タッチ、決定、喜ぶ、食事など |

これらの数は**まだ確定ではなく、素材制作の負担と実機性能を見て調整する案**です。

## 3-3. なぜアニメ素材がたくさん必要になるのか

アニメーションは、多くの場合、少しずつ異なる画像を順番に表示して作ります。

たとえば：

```text
待機アニメ

画像1 → 画像2 → 画像3 → …… → 画像12 → 画像1
```

さらに、衣装が変わると、動きごとに衣装を反映した画像が必要になる可能性があります。

例として、**衣装3種類 × 動き8種類 × 各30コマ**をすべて別画像にすると、合計720コマです。256×256・RGB565＋透明度という仮の形式では、画像だけで約135MiBになります。

これはあくまで概算ですが、**画像を作る作業量が大きくなりやすい**ことが分かります。

そのため、次の工夫を使います。

- 背景とキャラクターを分ける
- まばたきなどの小さな動きを再利用する
- 食べ方をいくつかの共通パターンにまとめる
- 最初から全衣装・全動作を作らない

# 4. CHIMMYの画像・アニメを作る方法

## 方法A：2D画像を編集して動かす

**最初の試作におすすめです。**

```text
利用条件を確認した基準画像
    ↓
画像編集で目・口・腕などを少しずつ変更
    ↓
透過PNGを複数作成
    ↓
端末で順番に表示
```

### 必要なもの

- 利用条件を確認した基準画像
- 画像編集ソフト
- まばたきや喜ぶ表情などの差分画像
- フレームの順番・表示時間を記録するデータ

### 特徴

- まばたきや小さな動きを始めやすい
- 顔の形や色を統一しやすい
- 複雑な全身の動きは、追加の作画や編集が必要

## 方法B：AI動画からコマ画像を作る

```text
利用条件を確認した基準画像
    ↓
AIで短い動きを作る
    ↓
FFmpegなどで画像を切り出す
    ↓
背景除去・位置合わせ・不要なコマの修正
    ↓
端末用の素材に変換
```

AIは制作の手間を減らせますが、**顔や衣装が途中で変化する、背景が透過されない、ループが不自然になる**ことがあります。

動画を作っただけで完成ではなく、仕上げ作業も必要です。

## 方法C：3DモデルをBlenderで動かす

```text
利用可能な3Dモデル
    ↓
Blenderでポーズ・衣装・動作を作る
    ↓
透過背景の画像として書き出す
    ↓
ESP32では2D画像として再生
```

衣装や動作を多数作る場合に有力ですが、最初に次の確認が必要です。

- モデルを利用してよいか
- ダウンロードできるか
- 手足を動かせるリグがあるか
- 表情や衣装を変更できるか

以前候補に挙がったSketchfabのモデルについては、**これらをまだ確認できていません**。

> CHIMMYのキャラクターの権利と、個々の画像・3Dモデル作者の利用条件は別です。個人制作でも、素材を自由に転載・配布できるとは限らないため、素材ごとに条件を確認します。

# 5. 音声と繁体字中国語の素材

## 音声

最初は、短い音を4種類程度用意すると試しやすいです。

1. タッチ音
2. 決定音
3. 喜ぶ音
4. 食事の音

自分で録音した音や、利用条件を確認した効果音を使えます。公式音声をそのまま使う前提にはしません。

初期試験の音声形式は、メーカーの音声サンプルに合わせて、**16kHz・16bit PCM**を候補とします。最終的な形式やモノラル／ステレオの扱いは実機で決めます。

## 繁体字中国語

ボタンやメッセージ用に、繁体字を表示できるフォントが必要です。

画面の文言例：

- `遊戲`：ゲーム
- `待機`：待ち受け
- `時鐘`：時計
- `餵食`：食事
- `玩耍`：遊ぶ
- `換裝`：着せ替え
- `設定`：設定

フォントの候補として **Noto Sans TC** があります。文字をすべて端末に入れると容量が大きくなるため、まず必要な文字を選んで使います。フォントのライセンス条件も確認します。

# 6. 実際の制作手順

## STEP 0：現状を保存する

最初に、現在の状態を戻せるようにします。

- 現行の`電源スケッチ`を保管
- Arduino IDEのボード設定を記録
- Arduino-ESP32とライブラリのバージョンを記録
- microSD内に必要なデータがあればバックアップ
- 電池・スピーカー・SDカードの型番と接続を確認

**新しいプログラムを書き込むと、現在動いているファームウェアは置き換わります。**  
ソースを保管するだけでなく、同じ設定で戻せるかを確認してから進めます。

## STEP 1：画面・タッチ・音・SDを個別に試す

メーカーのサンプルを参考に、1つずつ試します。

| 確認 | 方法の例 | 成功の目安 |
|---|---|---|
| 画面 | `01_HelloWorld` | 文字が正しい向きで表示される |
| 画面・タッチ | `05_LVGL_Widgets` | 指で押した位置と反応位置が合う |
| 電源情報 | `03_LVGL_AXP2101_ADC_Data` | USB・電池情報を確認できる |
| スピーカー | `07_ES8311` | 短い音を正常に再生できる |
| microSD | 基板用の小さな確認プログラム | 画像などの既知ファイルを読み込める |
| RTC | RTC確認用の小さなプログラム | 日時を書き込み、読み戻せる |

SDとRTCの確認には、別途小さなプログラムを用意する可能性があります。

なお、現在の電源スケッチは**無操作で30秒後に画面を消す設定**なので、試験中に画面が消えても、必ずしも故障とは限りません。

## STEP 2：静止画を表示する

1. 背景画像を表示する
2. その上にキャラクターの透過画像を重ねる
3. タッチした位置を検出する
4. タッチ時に文字や色を変える

**この段階の完成形：**  
「部屋の中にキャラクターがいて、触ると反応する画面」

## STEP 3：短いアニメと音を同時に動かす

1. まばたきなどの画像を複数枚用意
2. 順番に表示してアニメ化
3. タッチ時に効果音を再生
4. microSDから素材を読み込む
5. 表示の滑らかさ、音切れ、タッチの反応を確認

設計上の初期目標は**15fps**ですが、現時点では保証できません。ここで実機性能を測って、最終的な画像サイズや形式を決めます。

## STEP 4：時計を作る

1. 時刻・日付・曜日を表示
2. 香港の時刻で表示
3. Wi-Fiによる時刻同期を試す
4. Wi-Fiが使えない場合の手動設定を用意
5. 電源OFF後にRTCがどの程度時刻を保持するか確認

時刻同期を使う場合は、**2.4GHz Wi-Fi**が必要です。同期後も常時インターネットにつながなければ使えない設計にはしません。

## STEP 5：3つのモードを作る

- **ゲームモード**：食事・遊び・着せ替え
- **待ち受けモード**：CHIMMYと部屋を表示
- **時計モード**：時刻を大きく表示

3モードで同じ育成状態を共有し、モード変更で衣装や状態が消えないようにします。

## STEP 6：育成・保存を作る

1. 満腹度、機嫌、体力、眠気、親密度を管理
2. 食事や遊びで値を変える
3. 衣装と設定を保存
4. 電源を切っても復元できるようにする
5. OFF中の経過時間を上限付きで反映する

死亡・病気は入れず、**BABY CHIMMYの姿を維持しながら、親密度や反応の解放で成長**させます。

## STEP 7：電池・ケース・長時間運用

基本機能が安定してから：

- 電池の安全条件を確認
- 消灯・再表示を確認
- USB給電と電池給電の切り替えを確認
- 長時間表示時の発熱・消費電力を測定
- 本体・電池・スピーカーに合うケースを検討

駆動時間は、電池容量や画面の明るさによって変わるため、**実測前には断定できません**。

# 7. 最初に準備するものリスト

まずは、次だけを確認すれば制作を始められます。

- [ ] 現在のスケッチとArduinoの設定
- [ ] お持ちのmicroSDの容量・形式
- [ ] PCでmicroSDを読み書きできるか
- [ ] スピーカーの型番・接続状態
- [ ] 電池の型番・容量・充電条件・極性
- [ ] 試験に使える仮画像、または利用条件を確認した素材
- [ ] 画像を編集するソフト

**最初の目標は「背景の上にキャラクターを表示し、触ると反応する」ことです。**  
それができてからアニメ・音・時計・育成を順番に足していくのが、手戻りの少ない進め方です。
