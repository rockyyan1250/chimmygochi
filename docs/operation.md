# 実装・操作・素材差し替えガイド

対象：Waveshare ESP32-S3-Touch-AMOLED-2.16 / CHIMMY GOCHI v0.1。
設計書の最終完成版ではなく、SD素材を差し替えられる実機用プロトタイプ。

## 1. 今あるもの・必要なもの

- 端末本体、データ通信対応USBケーブル、microSD、開発PC。
- 音を鳴らす場合は端末に対応するスピーカー。
- 電池はUSB動作の必須条件ではない。種類・極性・定格が未確認の電池を新たに接続しない。
- 素材制作には透過PNGを出せる画像ソフト、WAVを出せる音声ソフト。
- ケース、充電器、電池の追加購入は実装確認後でよい。

この端末では16MiB Flash、8MiB PSRAM、約31.9GBのSD容量を検出した。
SDは端末からSPIで読み書きできるため、今回の素材導入にカードリーダーは不要。
既存SDデータは消去・フォーマットしていない。

**充電について**：起動時にAXP2101の主電池・バックアップ電池充電を停止し、
レジスタを読み戻して確認する。USBの `status` に
`charging_disabled_verified: true` が出ることを確認する。
確認に失敗した場合は電池を外し、USBだけで使用する。充電再有効化のUIはない。

## 2. 操作

| 表示 | 操作 |
|---|---|
| 遊戲 | 育成画面。飽足・心情・體力を0～100で表示 |
| 待機 | キャラクターと小時計。狀態ボタンで診断画面 |
| 時鐘 | 大時計、日付、曜日、午前午後、時刻取得元 |
| 設定 | スクロール式。明るさ・音量・消灯・夜間静音・時計・起動画面など |
| 餵食 | 飯糰、布丁、草莓、蘋果、三文治、牛奶の6種類 |
| 玩耍 | ボールの短い演出、または5個の泡をタップするミニゲーム |
| 換裝 | 仮素材では薄荷・薰衣草・蜜桃の3色 |
| 睡覺 / 起床 | 手動で就寝・起床。寝ている間は食事・遊び不可 |
| キャラクターをタップ | 短い反応。親密度40以上で別の反応 |

泡遊びは30秒以内に5個タップすると報酬。途中で戻った場合は報酬なし。
死亡・病気・年齢による姿の変更はない。満腹や疲労時は行動を断る。
食事・遊びで親密度が増え、睡眠で体力が回復する。
食べ物と服の種類数は現段階では固定。素材だけで新しいゲーム処理は追加できない。

画面上部の「電量」は、AXP2101が報告する推定残量を約1秒ごとに更新する。
ゲーム・待機・時計・設定・各メニュー・泡遊びで共通して表示する。
「電量 --」は主電池未接続、「電量 ERR」はPMICとの通信・電池検出・残量計・値の
いずれかが不正で取得できない状態を示す。0～100%以外の値は表示しない。
これは残量の推定値であり、電池の公称容量（mAh）や実測駆動時間ではない。
電池の特性が未設定のため精度は未確認。精度を上げる目的でも仕様未確認の電池を充電しない。
消灯中は表示も見えず、画面を点灯すると再び確認できる。

### 電源・消灯

- 操作なし30秒で減光、ゲーム画面は45秒で待ち受けへ移動。
- 初期設定では120秒で消灯。時計を常時表示する場合は設定の「無操作關屏」を「關」にする。
- 消灯後の最初のタッチは点灯専用。続けてタップすると操作できる。
- PWR短押し、またはGPIO18のユーザーボタンで画面を切り替える。
- PWR長押しは保存してPMICに電源断を要求する。USB接続状況によって完全遮断できない場合がある。
- 電池駆動時に3400mV未満が10秒続くと保存して電源断を要求する。
  このしきい値は保守的な暫定値であり、電池適合性・保護回路の保証ではない。
- 消灯中も育成処理は続く。deep sleepはまだ使用していない。
- 夜間静音の初期値は22:00～08:00。時計未設定時も音は抑止する。

## 3. 時刻と保存

表示は香港時間（UTC+8）、RTCにはUTCを保存する。
USB接続時はPCの時計を確認してから以下を実行する。

```sh
npm run device -- time
```

端末の「設定日期時間」から手動設定も可能。
Wi-Fiは明示的に同期するときだけ使用し、成功・15秒タイムアウト後に停止する。
SSID・パスワードの登録用USBコマンドはあるが、タッチキーボード・接続設定画面は未実装。
資格情報をシェル履歴、ログ、リポジトリへ残さないこと。通常はUSB時刻合わせだけで使える。

育成状態はFlashの専用NVSへCRC付き96バイト記録を2世代交互に保存し、書込後に読み戻す。
通常は約1分ごと、食事や設定変更などは約2秒後に保存する。
電源断で最後の未保存分が失われる可能性はある。

起動時にRTCが有効なら、保存時刻との差を最大12時間まで育成へ反映する。
設定では上限を1/6/12時間に変更できる。RTCが無効・時計が逆戻りした場合は不明な時間を推測しない。
両方の保存が破損している場合は自動消去せず、設定画面で明示的にリセットする。

## 4. 開発環境の再現

macOSのArduino IDE同梱CLIを既定で使用する。別のCLIなら `ARDUINO_CLI` で実行ファイルを指定。
Node.jsは22.12以上（開発確認は24）。依存は
[package-lock.json](../package-lock.json) と [dependencies.json](../firmware/dependencies.json) に固定。

| 依存 | 実装版 |
|---|---|
| Arduino ESP32 core | 3.3.12 |
| LVGL | 8.4.0 |
| GFX Library for Arduino | 1.6.9 |
| SensorLib | 0.3.3 |
| XPowersLib | 0.2.6 |
| ArduinoJson | 7.4.3 |

GFX 1.6.4ではこのcoreのSPI APIと互換性エラーが出たため、ローカル環境だけ1.6.9へ変更した。
ユーザーの既存グローバルライブラリ・元スケッチは変更していない。
ESP32 coreはArduino IDEのボードマネージャーで事前に導入する。

リポジトリのルートで：

```sh
npm ci
npm run setup
npm run assets
npm run check
npm run build
npm run upload
npm run device -- time
npm run device -- install
npm run device -- status
```

`setup` は `.deps/arduino/libraries` に専用ライブラリを入れ、固定コミットのES8311ドライバーを取得する。
`assets` は初回のみ独自仮素材の元PNG/WAV/JSONを生成する。既存の元素材は上書き生成しない。
UI用繁体字フォントと時計用数字フォントも生成する。
`upload` は直前にビルドしたバイナリを書き込む。ソース変更後は必ず `build` を先に行う。

ポートが違う場合：

```sh
PORT=/dev/cu.usbmodemXXXX npm run upload
PORT=/dev/cu.usbmodemXXXX npm run device -- status
```

本端末では通常のUSB RTSリセット後にROM書込待機へ残る問題が発生した。
アップロードは115200 baudとwatchdog-resetを使用し、USB再列挙を待つようにしている。
高速baudへの変更は、watchdogリセット時のUSB切断でシリアルエラーになる場合がある。
Arduino IDEのシリアルモニターなど、同じポートを開く他アプリは閉じること。

## 5. CHIMMY素材への差し替え

現在の素材は独自の中立的な丸いキャラクター、室内背景、合成音。
公式CHIMMY画像・公式音声・音楽は取得・同梱していない。
後で利用条件を確認した素材を用意できたら、次の形式へ整える。

1. 初回の `npm run assets` でできる `assets/source/pack.json` を確認する。
2. 元素材とJSONを別の作業フォルダーへコピーして編集する。
3. 3衣装それぞれに1～12枚の透過PNGを用意する。推奨256×256、上限320×320。
   同じ衣装内は全コマ同じサイズ。各アニメーションが参照する番号は全衣装で有効にする。
4. 背景は480×480の不透明PNG。
5. 音は16kHz・モノラル・符号付き16bit PCM WAV、最大5秒。
   `tap/happy/eat/dress` の4枠を用意する。無音WAVでもよい。
   44バイトの標準ヘッダーに続くPCMのみを受け付け、追加メタデータチャンクは不可。
6. JSONの `outfits[].frames` をPNGのファイル名順、`name` を衣装表示名にする。
   パスは元JSONからの相対パス。`background`、`sounds` も指定する。
7. `clips` の8枠を編集する：
   `idle/tap/eat/play/sleep/dress/refuse/happy`。
   `frames` は0始まりのコマ番号、`durations` は各コマ16～5000ms、
   `loop` は真偽値、`sound` は4枠の名前または空文字。各クリップ最大32コマ。
8. 正式素材では `placeholder: false` にする。権利があることをソフトウェアが保証する指定ではない。
9. 変換・検証・フォント再ビルド・転送する：

```sh
node tools/assets.mjs /path/to/your/pack.json assets/pack
npm run check
npm run build
npm run upload
npm run device -- install
```

画像と音だけの変更ならファーム書込は不要。
衣装名に新しい文字を使った場合はフォントが変わるため `build`・`upload` も必要。
生成物と元素材はGit管理外。大切な元素材は別途バックアップする。

変換後はCGA1形式（16バイトヘッダー＋RGB565、キャラは1ピクセル3バイトでアルファ追加）とWAVになる。
衣装アトラスは各3MiB以下。初期パックは背景・3アトラス・4音・manifestの9ファイル、約5.2MB。
USB転送は1024バイト単位で行い、SHA-256、サイズ、マニフェスト、全衣装を検証する。
転送後の全衣装検証中は数秒間UIが止まるため、通常操作中ではなく素材更新時に実行する。

SD保存先は `/chimmygochi/packs/pack-<時刻由来ID>/`。
同名ファイルへ上書きせず、検証完了したパックだけ有効にする。
転送失敗時は旧パックを維持し、新しい不完全ファイルは `.part` のまま残す。
不要な古いパックは、電源を切ってSDをPCへ移してから、対象を確認して手動削除する。
有効なパックや他アプリのデータを削除しないこと。

## 6. 実装構成

- [App.cpp](../firmware/ChimmyGoChi/App.cpp)：画面、操作、育成タイミング、時刻、USBコマンド。
- [GameModel.h](../firmware/ChimmyGoChi/GameModel.h)：育成計算、範囲検査、保存符号化・CRC。
- [Board.cpp](../firmware/ChimmyGoChi/Board.cpp)：QSPI画面、I2Cタッチ/RTC/PMIC、I2S音声。
- [Assets.cpp](../firmware/ChimmyGoChi/Assets.cpp)：SD、別タスクの素材ロード、検証・転送。
- [SaveStore.h](../firmware/ChimmyGoChi/SaveStore.h)：NVS保存。通常更新時の全消去は禁止。

LVGLはメインタスクだけで操作する。現在の衣装・背景・音をPSRAMに置く。
表示は480×24ピクセルの内部DMAバッファ2個、診断キャプチャはPSRAM上の480×480 RGB565。
音声タスクは再生データのコピーを所有し、衣装切り替え後も解放済みメモリを参照しない。
SDは画面QSPIと別のSPIホストを使い、読み書きをmutexで直列化する。

現行Flash配置：

| 用途 | オフセット | サイズ |
|---|---|---|
| 標準NVS（Wi-Fi・有効素材ポインター） | 0x9000 | 0x5000 |
| PHY | 0xe000 | 0x1000 |
| factoryアプリ | 0x10000 | 0x600000（6MiB） |
| gamesave NVS | 0x610000 | 0x10000 |
| core dump（障害診断用） | 0x620000 | 0x10000 |

OTAスロットはない。Arduinoのビルド表示の最大16MBではなく、アプリ上限は6MiB。
初回導入は旧アプリのパーティション配置を変えるので、必ずFlash全体を先にバックアップする。
今回、新規割当のcore dump領域に旧データが残っていたため、その64KiBだけ初期化した。
育成保存・標準NVS・SDはその操作の対象外。通常のアップロードではこの領域を消去しない。
別の端末で同じ警告が出た場合も、保存済みの障害情報か旧アプリの残骸かを確認してから対処する。
`npm run upload` はこの配置に合わせ、0xe000のPHY領域にOTA用 `boot_app0.bin` を書かない。
Arduino IDE標準の書込設定はこの領域を上書きするため、このパーティション配置には使わない。
2026-10-31の更新時に旧書込設定が0xe000から8KiBを上書きしたことを確認し、書込設定を修正した。
育成保存・SDには重ならず、起動・RTC・素材読込は確認済み。PHY領域を推測で消去・復元しておらず、
今回のSDK設定ではPHY初期データのパーティション読込は無効で、初期データはファーム内に含まれる。
ただしWi-Fiの実接続は未確認。

## 7. 診断と検証

```sh
npm run check
npm run test:battery
npm run device -- status
npm run device -- verify-battery
npm run device -- capture build/device.png
npm run device -- verify
```

`test:battery` は残量0%・100%、未接続、通信失敗、残量計無効、範囲外の値を
ホスト上で確認する。USBの `status` には `battery_state`、`battery_percent`、
画面の `battery_text`、直近の取得時刻 `battery_sample_ms` が含まれる。
未接続・取得失敗の `battery_percent` は `null` となる。
`verify-battery` は画面を切り替えて残量表示の描画・幅・消灯中の更新・再点灯を確認し、
元の画面と点灯状態に戻す。
泡遊びは起床中かつ体力が十分な場合に確認し、完了せずに戻るため報酬は増えない。
泡遊び中・時刻編集中・素材読込中は試験を開始しない。

`verify` は接続した実機で画面遷移、睡眠中の拒否、食事・ボール・泡遊び、
3衣装、入力拒否、消灯・点灯、保存・再起動後の親密度/衣装/RTC/有効パックを確認する。
**テストによって親密度・食事・体力などの育成状態が進む。初期化はしない。**
体力800以上（表示8以上）が必要。手動タッチや実際に聞こえる音の試験ではない。

実機で確認した項目と未検証項目を分ける：

- 確認済み：ビルド・書込照合、8MiB PSRAM、SDマウント、素材全ファイルの転送照合、
  タッチIC・音声回路の初期化、RTC書込/読戻し、画面キャプチャ、充電停止のレジスタ確認。
  実機自動試験で食事・睡眠・ボール・泡遊び・3衣装・入力拒否・消灯/点灯、
  再起動後の親密度・衣装・素材パック・RTC・保存世代の維持を確認した。
  素材読込後の測定値は内部空きヒープ約81KB、空きPSRAM約5.77MB、音声書込失敗0回。
- 手動確認が必要：物理画面の見え方、指タッチの座標、スピーカーの音質・音量、
  PWR操作、USBを外したRTC保持、電池持続時間・温度・低電圧時動作。
- 未達/未測定：全画面で15fps以上の保証、長期連続動作、電断故障注入、SD抜差し耐性、
  Wi-Fi/NTPの実ネットワーク接続、deep sleep、自由な衣装数、食べ物/玩具固有の画像レイヤー。

時計・素材に不具合があれば、`status` と `monitor 30` のログで確認する。
画面キャプチャは表示用フレームバッファの内容であり、液晶の物理的な写真ではない。
USBの `control` 応答 `ok` はコマンドを処理したという意味であり、満腹・睡眠などによる
ゲーム行動の拒否は画面通知と `status` の状態で確認する。

## 8. 元の端末状態への復旧

今回の書込前に16,777,216バイトの全FlashバックアップをPCのローカルセッション保管領域へ保存済み。
ファイル名は `pre-chimmygochi-flash.bin`、SHA-256は
`44ff21e685018fa018495f5cdc4f3e4c43049260edcbdce3747c04a16b33f957`。
個人設定を含む可能性があるのでGitや外部サービスへ公開しない。
セッション保管場所から、必要に応じて自分の安全な長期バックアップ先へ保管する。

復旧は現在の育成保存・設定を置き換える操作なので、必要なときだけ行う。
接続先とバックアップのハッシュを確認してから、esptoolでそのファイルをアドレス0へ書く。
手順例（自分の実行ファイル・バックアップ絶対パスへ置き換える）：

```sh
esptool --chip esp32s3 --port /dev/cu.usbmodem2301 --after watchdog-reset \
  write-flash --flash-mode keep --flash-freq keep --flash-size keep \
  0x0 /absolute/path/pre-chimmygochi-flash.bin
```

SDカード上のファイルはFlash復元では変更されない。
元の `AMOLED_PowerSwitch` スケッチは変更していない。
